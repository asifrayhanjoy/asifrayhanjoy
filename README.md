### 🏛️ Engineering Philosophy & Core Architectural Pillars

┌─────────────────────────────────┐      ┌─────────────────────────────────┐      ┌─────────────────────────────────┐
│   Zero-Compromise Type Safety   │ ───> │     Decoupled Service Layers    │ ───> │   Resilient Client Automation   │
│ Strict TS & Prisma Schemas      │      │ REST, WebSockets & Secure RBAC  │      │ MutationObservers & MV3 Workers │
└─────────────────────────────────┘      └─────────────────────────────────┘      └─────────────────────────────────┘


1. **End-to-End Type Safety Over Speculation:** Data contracts must remain immutable from the database tables via Prisma ORM down to client-side component props. Catch bugs during compilation rather than in customer production environments.
2. **Defensive Browser & DOM Engineering:** Client-side automation and Chrome extensions must be deterministic. By utilizing isolated state flags, debounce mechanisms, and scoped DOM queries, memory leaks, infinite loops, and layout thrashing are strictly prevented.
3. **Decoupled, Scalable Workflows:** Backend services should enforce separation of concerns. Authentication, transactional business logic, and automated cron pipelines are segregated to enable horizontal scalability and frictionless code maintenance.
4. **Pragmatic Production Speed:** Bridging prototype velocity with production hardening. Writing clean, self-documenting code, enforcing rigorous PR reviews, and utilizing AI-augmented tooling without compromising architectural discipline.
